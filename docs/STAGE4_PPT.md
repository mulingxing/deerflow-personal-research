# 第四阶段：PPT 生成

在聊天顶部进入“生成 PPT”页面，可以粘贴研究报告、讲稿或学习笔记；已有研究报告也可从报告工具栏带入该页面继续编辑。选择风格后生成并下载 `.pptx` 文件。

## 风格

页面提供五种真实渲染的封面预览：Marp 自带的 `default`、`gaia`、`uncover`，以及项目自带的 `midnight`、`paper`。后两种使用项目内的 CSS 主题；所有主题选项都由后端白名单校验，不接受任意 CSS 文件路径。

Marp 是把 Markdown 幻灯片转换为演示文件的工具。当前常规 PPTX 将每页渲染为图像，适合放映和分享，但页面内的文字通常不能在 PowerPoint 中逐项编辑。

## 排版保护

后端会先将内容过多的页面拆开。表格跨页时会重复表头，然后用所选主题实际渲染并检查文字是否超出页面。若再次拆页后仍放不下，生成会明确报错，避免下载文字被裁切的 PPT。特别长且无法拆开的段落或表格单元格需要先精简内容。修改后端代码后，需要重启项目才能应用新逻辑。

## 运行要求

项目的 `web` 依赖包含固定版本的 Marp CLI，后端优先使用项目内的 Node.js 和 `web/node_modules/@marp-team/marp-cli/marp-cli.js`，无需全局安装 `marp`。转换 PPTX 还需要本机浏览器；Windows 下优先寻找 Microsoft Edge。若路径不同，可在 `.env` 中设置 `MARP_NODE_PATH`、`MARP_CLI_PATH` 或 `MARP_BROWSER_PATH`。

默认不加载内容中的远程图片或本地图片路径；图片的文字说明会保留。Markdown 引用式图片及其链接定义、HTML 媒体标签、内联样式与 Marp 背景图指令也会被移除。这样可避免转换时访问资料里未知的网址，模板自身的配色、纹理和装饰不受影响。只有确认图片来源可信时，才可设置 `MARP_ALLOW_REMOTE_IMAGES=true`，启用标准 Markdown 中的公开 http(s) 图片。引用式图片和原始 HTML 媒体始终禁用。即便启用，后端仍拒绝字面上的本地地址和内网 IP；域名解析或重定向不能作为强出站安全边界，因此不要用于处理不可信来源的图片链接。

生成幻灯片要点时仍会使用项目配置的大模型；若模型在云端，输入内容会发送给模型服务。转换工作在本机进行，临时 Markdown 和 PPTX 文件会在请求结束后删除。
